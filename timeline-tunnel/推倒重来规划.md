# 推倒重来规划

## 1. 目标与原则
- 保留旧项目的核心亮点：高性能渲染、丰富布局、动画机制、可扩展性、现代前端工程实践。
- 解决旧项目的主要难点：螺旋布局算法的可维护性与扩展性、动画机制的流畅性与可控性。
- 采用更清晰的架构分层，提升类型安全、可测试性和可维护性。
- 以“时光隧道”沉浸式体验为核心驱动力，兼顾线性/离散等多种布局。

## 2. 技术选型
- React + PixiJS + TypeScript
- Vite 作为开发与打包工具
- 代码质量工具：ESLint、Prettier
- 状态管理可选用轻量方案（如 Zustand、Jotai），如需复杂交互再考虑 Redux

## 3. 架构与模块划分
- timeline-core：核心算法与类型（布局、动画、数据结构、工具函数等）
- timeline-renderer：PixiJS 渲染层，负责节点、连线、动画等渲染细节
- timeline-react：React 组件封装，负责交互、状态管理、与外部集成
- timeline-demo：mock 数据与交互示例，便于开发和演示

## 4. 螺旋布局重构思路
- 采用参数化 3D 螺旋公式，明确每个参数的物理/视觉意义（圈数、密度、半径、切面、视角等）
- 提供布局参数配置与实时调试面板，便于调优
- 支持切面聚焦、滚轮穿梭、节点高亮等核心交互
- 节点投影、缩放、透明度等视觉效果采用统一的插值与映射函数，便于维护

## 5. 动画机制优化
- 明确“离散-重聚”双阶段动画的时序与状态流转
- 动画参数（时长、缓动、批量控制）集中管理，支持全局与局部动画配置
- 充分利用 gsap timeline 的分组与嵌套能力，提升动画表现力
- 支持动画中断、回退与重播，提升交互体验

## 6. 类型与接口设计
- 所有核心数据结构（节点、布局、动画、事件等）均采用 TypeScript 类型定义
- 对外暴露清晰的 API，便于二次开发与集成
- 关键算法与渲染逻辑单元测试覆盖

## 7. 其它建议
- mock 数据与真实数据解耦，便于开发和演示
- 代码注释与文档完善，便于团队协作和后续维护
- 预留无障碍与响应式支持接口

---

本规划旨在充分吸取旧项目经验，推倒重来，打造更具可维护性、扩展性和沉浸体验的时间线组件。
