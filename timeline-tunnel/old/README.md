# 项目需求

1. 高性能时间线组件，基于 PixiJS 实现，支持大量节点的高效渲染与交互。
2. 组件化设计，核心功能（渲染、布局、数据、类型、工具等）分模块组织，便于维护和扩展。
3. 支持多种时间线布局（如线性、螺旋、离散等），可灵活切换。
4. 类型安全，独立类型定义文件，确保数据结构和接口的类型安全。
5. 易用性与可扩展性，对外暴露清晰的组件接口，方便集成和二次开发。
6. 提供 mock 数据和示例，便于开发、调试和演示。
7. 现代前端工程实践，采用 React 组件封装，结合 PixiJS 渲染，支持主流前端开发流程。
8. 节点需按时间顺序清晰可视化，便于理解事件发展脉络。
9. 动画转场需流畅且富有表现力，提升交互体验和视觉吸引力。
10. 螺旋（时光隧道）布局下，支持通过鼠标滚轮控制当前聚焦的螺旋切面，实现如“时光隧道”般的沉浸式浏览体验。
11. 节点支持类型、分组、层级、图片等多样化信息表达，交互时有放大、变色、弹窗等丰富反馈。
12. 支持大数据量下的流畅渲染与动画，必要时可虚拟化或分批渲染。
13. 节点样式、弹窗内容、动画参数等均可扩展和自定义。
14. 支持键盘导航、无障碍标签、响应式布局等辅助功能。

## 关于“时光隧道”螺旋布局的体验描述

- 节点沿螺旋路径依时间顺序排列，视觉上形成“隧道”或“时空回廊”效果。
- 用户可通过鼠标滚轮（或手势）前后穿梭，聚焦于某一时间段的节点切面。
- 滚动时，节点在螺旋上动态缩放、透明度渐变、前后遮挡，营造强烈的纵深感和沉浸感。
- 当前聚焦的切面节点会被高亮、放大、居中显示，历史与未来节点则逐渐远离、变小、淡出。
- 切换切面时有流畅的动画过渡，仿佛穿梭于时光隧道。
- 支持自定义螺旋参数（圈数、密度、半径、动画曲线等），适配不同场景。

## 当前实现的主要难点与遗留问题

1. **离散-重聚动画机制未完全打通**
   - 理想状态下，每次布局切换都应分为“离散”（节点先飞散到远处/角落/随机位置）和“重聚”（节点再以动画聚合到新布局）两个阶段，形成流畅且富有表现力的转场。
   - 实际开发中，由于“离散/重聚”动画的时序、批量 gsap timeline 控制等问题（详见 `gsap心得.md`），以及 zoom（缩放）参数未调优，导致动画效果不理想。例如，zoom 太低时，只有中心节点高速运动，动画观感极短，无法展现完整的转场过程。
   - 目前只能通过按钮手动测试离散和重聚，未能实现自动、自然的双阶段转场。

2. **螺旋（时光隧道）布局的参数与交互难以扩展**
   - 螺旋布局的实现依赖大量参数调试，且采用了较为“感性”的算法（非严格 3D 坐标），虽然能实现一定的视觉效果，但代码难以维护和扩展。
   - 由于参数复杂且缺乏系统性，难以支持如视角拖动、滚轮切换切面等更丰富的交互。即使通过反复调参实现了某种效果，也难以保证美观和可控性，后续扩展性较差。
   - 若需实现更自然的“时光隧道”体验，可能需要重新设计螺旋算法和参数体系。

## 关于螺旋布局的算法思考与实践体会

- 理论上，采用严格的 3D 坐标变换可以实现节点在空间中的螺旋排布，但实际效果往往难以达到理想的“和谐感”。
- 我曾尝试让节点近似于多个斐波那契螺旋线或渐开线螺旋排布成一周，期望在时光穿梭运动时，不同圈之间有一种非常和谐的视觉节奏。
- 实践中发现，单纯依赖 3D 转换难以获得这种感觉，反而通过参数化的二维投影、非线性缩放、透明度渐变等“感性”算法，更容易实现近似和谐的时光隧道效果。
- 这为后续算法设计提供了启发：不必拘泥于严格的几何推导，可以结合美学和交互体验，灵活调整参数与映射关系，追求主观上的“好看”和“沉浸”。但是这种感性的公式，由于很多参数并没有严格的物理意义，难以继续维护下去。
