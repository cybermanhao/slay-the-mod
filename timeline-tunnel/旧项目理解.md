# 旧项目理解

## 1. 项目目标与核心需求
- 实现高性能、可扩展的时间线组件，基于 PixiJS 渲染，支持大量节点的高效渲染与交互。
- 采用组件化、模块化设计，核心功能（渲染、布局、数据、类型、工具等）分模块组织，便于维护和扩展。
- 支持多种时间线布局（线性、螺旋/时光隧道、离散等），可灵活切换。
- 类型安全，独立类型定义文件，确保数据结构和接口的类型安全。
- 对外暴露清晰的组件接口，方便集成和二次开发。
- 提供 mock 数据和示例，便于开发、调试和演示。
- 现代前端工程实践，采用 React 组件封装，结合 PixiJS 渲染，支持主流前端开发流程。

## 2. 交互与体验
- 节点需按时间顺序清晰可视化，便于理解事件发展脉络。
- 动画转场需流畅且富有表现力，提升交互体验和视觉吸引力。
- 螺旋（时光隧道）布局下，支持通过鼠标滚轮控制当前聚焦的螺旋切面，实现沉浸式浏览体验。
- 节点支持类型、分组、层级、图片等多样化信息表达，交互时有放大、变色、弹窗等丰富反馈。
- 支持大数据量下的流畅渲染与动画，必要时可虚拟化或分批渲染。
- 节点样式、弹窗内容、动画参数等均可扩展和自定义。
- 支持键盘导航、无障碍标签、响应式布局等辅助功能。

## 3. 技术栈与工具链
- React + PixiJS + TypeScript
- 推荐使用 Vite/Webpack 等现代打包工具
- 代码质量工具（ESLint、Prettier 等）

## 4. 主要难点与遗留问题
- 离散-重聚动画机制未完全打通，动画时序和批量 timeline 控制有难点，zoom 参数影响动画观感。
- 螺旋布局参数与交互难以扩展，当前实现较为“感性”，维护性和扩展性不足，需重新设计更系统的算法和参数体系。
- 螺旋布局的算法实践体会：严格 3D 坐标变换难以获得理想效果，参数化二维投影、非线性缩放、透明度渐变等“感性”算法更易实现和谐的视觉体验，但难以维护。

## 5. 目录结构与代码模块
- gaussianRandom.tsx：工具函数，生成高斯分布随机数，用于节点分布或动画。
- gsap心得.md：动画库 GSAP 的使用心得和问题记录。
- layout.tsx：布局相关逻辑，支持多种布局切换。
- mockTimeLine.tsx：mock 数据和时间线示例，便于开发调试。
- timeline.tsx：时间线主组件，负责渲染和交互。
- timenodesprite.tsx：时间线节点的 PixiJS 精灵封装，负责节点的渲染与交互。

## 6. 螺旋布局与动画机制的具体实现分析
### 螺旋布局（calculateCircleLayout）
- 通过遍历节点，计算每个节点在圆形/螺旋上的位置。
- 主要参数有 maxArc、start、end、circleRadius、minScale/maxScale 等。
- 节点的 x/y 由三角函数和 scale 计算，scale 决定了节点的投影深度和大小，z 用于插值。
- 只显示部分节点（visiblelimit），其余节点 display=false。
- 这种实现方式是“二维投影+非线性缩放”，并未严格采用 3D 螺旋公式，参数较为感性，维护和扩展性有限。

### 动画与布局切换
- TimeNodeSpriteManager 支持多种布局切换（lineV、lineH、circle、fadeaway、sand 等）。
- 切换到 circle 布局时，先做一次“fadeaway”离散动画，再做 circle 动画，形成“离散-重聚”双阶段转场。
- 动画通过 gsap.timeline 批量控制，duration 随节点序号变化，形成渐进式动画。
- animateCircleLayout 负责螺旋布局的动画，onUpdate 时动态调整节点可见性。
- 目前动画机制存在“离散-重聚”时序不理想、zoom 参数影响观感等问题，正如 README 所述。

### 交互与节点表现
- TimeNodeSprite 支持鼠标悬停放大、点击弹窗等交互，zIndex 动态调整，动画有弹性效果。
- 节点颜色、大小、可见性等均可扩展，支持类型分组和自定义纹理。
